# Material 3 Expressive — house rules

The design system for this site. M3 supplies the *engineering*: tonal colour,
contrast guarantees, a shape scale, spring motion, a type scale with a second
weight axis. The site supplies the *face*: warm paper, near-black ink, Fraunces,
halftone, painterly dusk. Nobody should look at a page and think "Google".

Tokens live in `src/styles/m3-tokens.css`, generated by `npm run tokens`.
Never hand-edit that file.

## Colour

Use role tokens. Never a raw hex, never `light.rule` or the old `cs.*` colour
constants in new code.

```css
color: var(--md-sys-color-on-surface);
background: var(--md-sys-color-surface-container-low);
border: 1px solid var(--md-sys-color-outline-variant);
```

Themes are set with `data-theme` on a container:

| value | who | ground |
|---|---|---|
| `ryukijano` / `ryukijano-dark` | graphics & systems | slate-blue #6f9fd8 |
| `ryoushi` / `ryoushi-dark` | quantum algorithms | magenta #b04a75 |
| `study` / `study-dark` | case studies | terracotta #c96442 |

The neutral ramps are seeded from this site's paper (#E6E1D3) and ink (#161618),
*not* from the accent. That is deliberate and is why every light surface sits at
hue ~39 whichever persona is active. Don't "fix" it.

Pairing rule: every `X` has an `on-X`. Text on `surface-container` uses
`on-surface`. If you find yourself picking a colour by eye, you've left the
system.

## Shape

Ten steps, `--md-sys-shape-corner-*`: `none, extra-small, small, medium, large,
large-increased, extra-large, extra-large-increased, extra-extra-large, full`.

**Optical roundness** — when nesting, the inner radius is not the outer radius:

```
inner = outer − padding
```

A card at `extra-large` (28px) with 14px padding wants ~14px inside, not 28.
Equal radii on nested boxes look wrong even when nobody can say why.

Shape is also a *state*. M3 Expressive morphs corners on interaction — a resting
`large` going to `extra-large` on press reads as physical. Use it on genuinely
interactive things, not on prose.

## Motion

Springs, via Google's published spring→curve table. Always pair the matching
duration with the matching curve:

```css
transition:
  transform var(--md-sys-motion-duration-expressive-default-spatial)
            var(--md-sys-motion-spring-expressive-default-spatial),
  opacity   var(--md-sys-motion-duration-expressive-default-effects)
            var(--md-sys-motion-spring-expressive-default-effects);
```

- **spatial** — anything that moves, resizes, rotates, or changes corner radius.
  These overshoot. That's the expressive part.
- **effects** — colour and opacity. These must *not* overshoot; a colour that
  overshoots goes out of gamut and looks like a bug.

Mixing them up is the single most common M3 motion error. Opacity on a spatial
curve visibly flickers past its target.

Honour `prefers-reduced-motion`. `base.css` already zeroes durations globally;
don't re-enable them locally.

## Type

M3 splits the scale into a **brand** face for Display/Headline and a **plain**
face for Body/Label. That is natively Fraunces + Inter here, which is why the
mapping needed no compromise.

```css
font-family: var(--md-sys-typescale-headline-large-font);
font-size: var(--md-sys-typescale-headline-large-size);
line-height: var(--md-sys-typescale-headline-large-line-height);
letter-spacing: var(--md-sys-typescale-headline-large-tracking);
font-weight: var(--md-sys-typescale-headline-large-weight);
```

Every role has an emphasized weight: `--md-sys-typescale-emphasized-<role>-weight`.
Use it for selected state, active nav, the one number in a paragraph that
matters. Not for whole paragraphs — emphasis that's everywhere is emphasis
nowhere.

Data, metrics, code and any figure that must align in a column: mono
(`--md-sys-typescale-mono-font`), tabular numerals.

## State layers

Interactive surfaces get a translucent layer of their *own* `on-` colour, not a
different background:

```css
.target::after {
  content: '';
  position: absolute;
  inset: 0;
  background: currentColor;
  opacity: 0;
  transition: opacity var(--md-sys-motion-duration-expressive-fast-effects)
              var(--md-sys-motion-spring-expressive-fast-effects);
  pointer-events: none;
}
.target:hover::after  { opacity: var(--md-sys-state-hover-opacity); }
.target:active::after { opacity: var(--md-sys-state-pressed-opacity); }
```

Focus is separate and must always be visible: a 3:1 outline, never removed.

## Elevation

`--md-sys-elevation-0..5`, tinted warm so shadows read brown rather than grey on
paper. On the dark ground prefer a lighter `surface-container-*` over a shadow —
shadows barely register on near-black, which is why M3 layers dark surfaces by
tone instead.

## What this does NOT mean

- No Material iconography, no Roboto, no Google Sans.
- No ripple that starts from the click point — too Android for a reading site.
  A state layer is enough.
- The painterly work stays: halftone, CRT scanlines, the wave, the dusk. M3 is
  underneath it, not instead of it.
- Existing case-study prose keeps its editorial voice. Material governs
  interactive chrome and the token layer, not paragraph rhythm.

## Checks

`npm run tokens` fails if any text pair drops below WCAG AA 4.5:1 (3:1 for
outlines). If you change a seed and it fails, change the seed — do not lower the
threshold.
